# 电视端分类浏览设计

日期：2026-09-01

## 背景

电视首页的分类行完全来自豆瓣 `search_tags` 接口，电影和电视剧各 8 个：

```
movie  热门 最新 豆瓣高分 冷门佳片 华语 欧美 韩国 日本
tv     热门 国产剧 综艺 美剧 日剧 韩剧 日本动画 纪录片
```

只用了豆瓣四个可用维度中的一个。用户反馈「分类有点少」。

## 实测：豆瓣还能提供哪些维度

全部在 2026-09-01 用 curl 实测通过。

| 维度 | 接口 | 结果 |
|---|---|---|
| 预置标签 | `movie.douban.com/j/search_tags` | 已在用，各 8 个 |
| 榜单 | `m.douban.com/rexxar/api/v2/subject_collection/{id}/items` | 11 个 id 全部 200，Top250 共 250 部 |
| 类型 | `movie.douban.com/j/new_search_subjects?genres=` | 200，每页 20，可翻页 |
| 地区 / 年代 | 同上 `countries=` / `year_range=` | 200，可与类型组合 |

关键坑：**中文参数必须 URL 编码**，直接发原始 UTF-8 豆瓣返回 400。排查时我一度以为接口挂了，实际是自己没编码。

`new_search_subjects` 没有 type 参数，电视剧靠 `tags=电视剧` 表达。排序 `sort` 只接受 `U`(综合) `T`(热度) `S`(评分) `R`(最新)。返回数组在 `data` 下，`rate` 对未上映条目是空字符串。

## 目标

1. 分类维度大幅增加：类型 × 地区 × 年代可组合
2. **首页行数几乎不增加**——遥控器按不动是硬约束

## 非目标

- 不改手机端和桌面端的任何行为或样式
- 不改 `android-tv/` 的原生代码

## 决策一：分类做成独立页面，不往首页堆行

首页现在约 10 行。把类型、地区、年代都铺成行会变成 30 行以上，走到最下面要按几十次下键——分类变多了，却更难找。

因此新增 `/browse` 分类页，从顶栏进入。首页只补三行**高价值榜单**（豆瓣 Top250、正在热映、一周口碑榜），这三行是「不知道看什么」时最直接的答案，值得占首页位置。

## 决策二：`/browse` 是电视专用路由

现有电视页面（首页、收藏、设置）都是与手机共用路由、顶层按 `isTvLike` 分支。分类页手机端没有对应功能，因此非电视设备访问时 `router.replace('/')` 回首页。手机端不存在任何指向 `/browse` 的入口，这条路径正常情况下走不到。

## 决策三：筛选行 + 结果网格

```
[0] 电影 / 电视剧
[1] 类型：全部 剧情 喜剧 动作 爱情 科幻 动画 悬疑 惊悚 恐怖 犯罪 纪录片 战争 奇幻 冒险 历史 音乐 家庭 传记 武侠
[2] 地区：全部 华语 中国大陆 香港 台湾 美国 日本 韩国 英国 法国 德国 印度 泰国
[3] 年代：全部 2026 2025 2024 2023 2020年代 2010年代 2000年代 90年代 80年代
[4] 排序：综合 热度 评分 最新
[5+] 结果网格（5 列，keepColumn: true）
```

筛选行是横向 pill 条，与首页分类行同一套手感（左右走、到头停）。结果网格复用 `TvSearchResults` 已调好的 5 列 + `keepColumn: true` 走位——上下移动时保持列号，是网格唯一不别扭的行为。

每一维都有「全部」用于清空该维；选中态是填充底色（`bg-[#3b82f6]`），与设置页 OptionRow、首页顶栏一致，焦点移开后仍然可见。

## 决策四：结果为空要说话

类型 × 地区 × 年代三维组合很容易筛出 0 条（例如 泰国 × 武侠 × 80年代）。此时必须显示「没有符合条件的结果」并保持筛选行可聚焦，否则遥控器会卡在一个没有任何可聚焦元素的页面上——这是电视端最难自救的死局。

## 风险

| 风险 | 应对 |
|---|---|
| 豆瓣在境外部署不稳 | 沿用现有 revalidate 缓存；失败时行为与现有分类行一致 |
| 榜单 id 拼进上游 URL | 白名单校验，非白名单直接 400，不发上游请求 |
| 三维筛选结果为空 | 见决策四 |
| 首页变长拖慢遥控器 | 只加 3 行，且沿用行懒加载 |
